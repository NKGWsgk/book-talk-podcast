- 今回のテーマ案: ハッキングってどうやるの！？

## 一言で言うと

ニュースで聞く「脆弱性を突かれた」の中身は、魔法ではなく、入力フォームやパスワード試行など、見える経路から見えない内部処理を想像して隙を探す作業である。攻撃の手順を知ることは、防御の第一歩であり、現代のセキュリティは攻撃手法を隠すより公開して試せるようにする方向へ移っている。

## 要約

### 1. 導入：ニュースの向こう側

個人情報流出のニュースで「サイトの脆弱性を攻撃された」と聞く。だが攻撃する側が具体的に何をしているかは、聞き手にはピンと来にくい。今回の本編はその中身を追う。

冒頭で必ず置く断り:

- 他人のマシンやサービスへ無許可で攻撃するのは犯罪である
- 真似しない
- 説明するのは防御のために攻撃者の発想を知るためである

元ネタではこの断り自体をコメディにして長く使うが、次回作では短く事実として一度置き、以降は防御視点で通す。

### 2. 典型例その1：SQLインジェクション

最も典型的な攻撃の一つとして、ログインフォームへのSQLインジェクションを取り上げている。

背景の仕組み:

1. 多くのウェブサービスはログイン時、内部でSQLというデータベース操作用の言語を動かす
2. 典型的には「登録済みユーザーの表から、入力されたメールとパスワードが一致する行を探す」という問い合わせになる
3. 条件に合った行が見つかれば、その利用者としてログイン処理が進む

攻撃の発想:

- 入力欄に渡す文字列の中に、SQLの文として解釈される区切りや条件を紛れ込ませる
- 文字列として閉じるべき箇所を途中で終わらせ、常に真になる条件を足し、後ろのパスワード照合を無視させる
- 結果として、本来の照合をすり抜け、表の先頭に近い利用者などでログインできてしまう場合がある

ポイントは、利用者の画面にはSQL文が見えないことである。サーバー内部で完成しているはずの文を想像し、「ここにこう入れれば隙になる」と考える。鍵穴の音から内部構造を推測するピッキングに近い、と元ネタは述べる。

防御の話:

- 特定の記号を受け付けない消毒、いわゆるサニタイズ
- より強い方法として、SQL文の骨格を固定し、入力はデータとしてだけ渡す方式がある
- 入力フォームに命令を紛れ込ませる系統は、クロスサイトスクリプティング、OSコマンドインジェクション、ディレクトリトラバーサルなど複数ある
- 昔の素朴なフォームは隙が多かった。最近のテンプレートやフレームワークは、ある程度この対策を自動で入れるものが多い

### 3. ハッキングの精神その1：全ては想像力から始まる

見えない内部を想定し、入力の経路から試す。これが攻撃の出発点である、という整理。

元ネタの言い方:

- 謎解きやクイズに似ている
- 優れた攻撃手法は、美しいパズルの解法のように見えることがある
- ただし推奨しているのは攻撃ではなく、防御側が攻撃者の心を読むこと

台本転用時は「美しいハッキング」礼賛に寄せすぎない。想像力が防御に必要な理由として回収する。

### 4. 典型例その2：人から情報を取る／当たりを付ける

ログインフォームを見て「特定の人になりすまして入りたい」場合の発想。

1. メールアドレスは公開情報から取れることがある
2. パスワードが問題になる
3. 人との会話や公開発信からパスワードの傾向を探る手法がある。ソーシャルエンジニアリングと呼ばれる
4. 情報がなければ、総当たり、いわゆるブルートフォースがある。ダイヤル錠を一つずつ回すのと同じ発想
5. 文字種が多いと組み合わせは爆発する。8桁程度でも現実的に総当たりしきれないことが多い
6. そこで辞書攻撃がある。過去の大規模流出で実際に使われていたパスワードを、使われやすさの順にまとめたリストを上から試す
7. 有名な例として、ロックユーというソーシャルネットワークの流出をまとめたロックユーテキストが挙げられる
8. 世界でよく使われる弱いパスワードの例として、数字の連なり、password という単語、iloveyou、princess などが紹介される
9. 自動化する道具としてヒドラというツール名が挙がる。ギリシャ神話の多頭の怪物にちなむ命名

防御側の着地:

- 辞書に載るような分かりやすい文字列を使わない
- 一度流出したパスワードは辞書に載り、再利用が危険になる
- 自分が過去に流出に巻き込まれたかを調べられるサービスがある、という紹介がある
- パスワードマネージャでランダムな文字列を使う、という日常の対策へ接続する

パスワード回との接続:

- 辞書攻撃・使い回し・流出は、パスワードとパスキー回の「秘密を送る設計が弱い」話の具体例になる
- 今回は「攻撃者は何をしているか」側から同じ現象を見る

### 5. ハッキングの精神その2：トライアンドエラーと工夫

どの本や実務者の話でも、空振りは当然だとされる。侵入口を見つけるまで諦めない。ただし闇雲な総当たりだけでは効率が悪い。辞書のように、実績のある候補から試す工夫が、試行錯誤を現実的にする。

元ネタでは擬似環境、攻撃してよいと明示された練習用マシンで道具を試した体験が語られる。本番サービスへの無許可攻撃ではない、という線は台本でも残す。

### 6. 道具と学習コストの低さ

元ネタが強調する驚き:

- 辞書ファイルは普通に検索して見つかる
- 「7日間でハッキングを始める」系の入門書がある
- 攻撃用ツールが最初から入ったOSを入れれば、ヒドラなどもすぐ使える
- メタスプロイトという、既知の脆弱性へ向けた攻撃をまとめた枠組みがある

ここで聞き手が抱きやすい疑問:

> そんな道具を公開して大丈夫なのか。

### 7. メタスプロイトと公開の思想

元ネタの核の一つ。メタスプロイトを最初に知ったときは危険に見えた。知識がなくても指示を書けば攻撃できそうだからである。だが調べると思想は逆だった、と続く。

整理:

1. 攻撃キットめいたものは、 anyway 裏市場で出回る
2. 違法で隠すと、真面目なセキュリティ担当が試せなくなる
3. 許可を取って侵入を試す作業をペネトレーションテストと呼ぶ。貫く、侵入する、という語感
4. それを専業にする人もおり、ペンテスターと呼ばれる
5. 道具が表で使えることで、侵入テストが進み、防御を厚くできる
6. トップページの趣旨を噛み砕くと、「知識は力である。共有された知識はより強い力である。守護者が一歩先を行くための武器を提供する」といった内容になる

歴史の対比:

- 初期は隠蔽によるセキュリティ、脆弱性情報や攻撃手段を隠しておけば安全だ、という発想があった
- 隠した結果、破壊的な被害が繰り返し起きた、という反省がある
- いまはオープンにした方が社会全体としては良くなる、という方向へ移っている

オープンソース思想との接続:

- 都合の悪いこと、脆弱性情報であっても公開し、改善できる状態にする
- 臭いものに蓋をするのではなく、対策を進める
- 攻撃を理解することが、守るための第一歩である

### 8. 番組内の脱線（構成転用時の扱い）

元ネタには以下が多い。次回作の本線には使わない。

- 断り文句を炎上回避の呪文にするコント
- 子供の名前に攻撃文字列を付ける、文化庁の人名用漢字の話
- 大麻合法化、性教育、下ネタ、ムツゴロウ系の逸話
- 英語会話スクールの広告パート
- 「攻めが楽しい」方向の言い回しを何度も訂正する往復

転用してよい核だけ残す。

- 攻撃の中身は想像と試行である
- 入力への命令混入、人からの情報収集、辞書による当たり、が具体例
- 道具の公開は防御のための侵入テストを可能にする
- 隠蔽より開示、という歴史的な学び

## 次回作への転用ポイント

テーマ「ハッキングってどうやるの！？」に直結する核は次の線である。

| 観点 | 中身 |
|------|------|
| やることは何か | 見えない内部を想像し、入力・会話・試行の経路から隙を探す |
| 代表例 | SQLインジェクション、ソーシャルエンジニアリング、総当たり、辞書攻撃 |
| 必要な態度 | 想像力、空振りを前提にした試行、候補を絞り込む工夫 |
| 道具の位置づけ | 入門書・辞書・自動化ツール・メタスプロイトなどは、無許可攻撃のためではなく侵入テストと防御のためにも使われる |
| 社会の学び | 隠すより公開して試せるようにした方が、結果として守りは強くなる |
| 聞き手の行動 | 弱いパスワードをやめる、使い回さない、自分のサービスや入力の受け方を疑う |

聞き手が持ち帰る一文の候補:

> ハッキングの中身は、見えない仕組みを想像して試すこと。守りは、その想像を先に回すことから始まる。
