# 台本：ハッキングってどうやるの！？

みなさんは、映画やドラマで、ハッカーが黒い画面に緑の文字を打ち込んでハッキングするシーンを見たことはありませんか。そこでハッカーは、何を、どうやっているのでしょうか。

プログラミングの言葉は分からなくても、ロジックが分かれば、仕組みは追えます。今日は、みなさんが知っているログイン画面から、奥の動きを見ます。

ログインのとき、サービスは登録情報を保管したデータベースへ、SQLと呼ばれる文を送ります。データベースとは、登録情報を表の形で保管しておく仕組みです。送られる文の意味は、登録済みユーザーの表から、入力されたメールアドレスと一致し、かつ入力されたパスワードと一致する行を探せ、です。行が見つかればログインできます。

ここで大事なのは、メール欄とパスワード欄に入れた内容を、文の中でどう区切るかです。正しく扱うときは、入れた内容の始まりと終わりに印を付けて、ここからここまでが比べる材料です、とデータベースに伝えます。印で区切られているあいだは、保存されているパスワードと並べて比べるだけの材料であり、探す条件そのものとしては読まれません。

古い作り方では、その印の付け方まで含めて、パスワード欄に入れた内容を文の途中へそのままつなぎます。すると、パスワード欄の中に、終わりの印を先に書いてしまう入力ができます。終わりの印より後ろに書いた部分は、比べる材料ではなく、探す条件の続きとして読まれます。たとえば、終わりの印の直後に、または一は一に等しい、といったいつでも通る条件を足し、さらに後ろに残っていた本来のパスワード照合を、読み飛ばす印で無効にします。データベースから見ると、本物のパスワードが合っている必要はなくなり、いつでも通る条件だけで行が見つかったことになります。その結果、表の先頭に近い利用者などでログインできてしまう場合があります。

この系統をインジェクション、つまり注入と呼び、代表例がSQLインジェクションです。画面にはSQL文は見えません。奥ではメールとパスワードをつないだ文が組まれているはずだ、と想像し、パスワード欄から区切り方をずらします。当てる対象はパスワードそのものではなく、比べ方の文です。

パスワードそのものを当てにいく話もあります。特定の人のアカウントに入りたいとき、メールアドレスは公開情報から分かることもあります。残るのはパスワードです。片っ端から試す総当たりもありますが、使える記号や長さが増えると組み合わせは爆発し、現実的に試し切れないことが多いです。

そこで辞書攻撃があります。過去の大規模流出で使われていたパスワードを、使われた回数が多いものから順に並べたリストを試します。人のパスワードの付け方は定番に偏ります。キーボードの左上から順に押しただけの並び、数字を一から六まで並べただけの列、パスワードという英単語、アイラブユーのような短い定番、adminのような管理用の語、年号や名前に数字を足しただけの形が、何度も出ます。リストの先頭のごく一部だけで、流出したパスワードのかなりの割合を占めることもあり、全部を均等に探すより、偏りの強い先頭から潰す方が当たりやすくなります。

別のやり方として、どこかで流出したメールとパスワードの組を、別のサービスでも次々試すものがあります。定番パスワードを当てるのではなく、別サイトで本当に使われた組を横流しします。使い回しが多いほど通りやすくなります。

候補のパスワードを手で打ち直しているわけではありません。裏側ではメールとパスワードをサーバーへ送り、合否の返事をもらうだけです。攻撃する側のプログラムは、候補パスワードのリストをログイン宛先へ次々流し込み、失敗ならすぐ次へ進み、成功の返事が出た瞬間に通ったパスワードとして抜き出します。画面描画もボタン操作も要らず、人間が打つ間隔とは比べものになりません。

いま多くのサービスには入力回数の制限があり、同じアカウントや同じ接続元から失敗が続くと止まります。そのまま一気に流し込むだけでは止まりやすいので、回数のカウントが紐づく接続元を切り替えたり、別の入口や制限の弱い古い管理画面へ移したりして、制限をかわしたりカウントを振り直したりします。

こうした試し方を助ける辞書や道具は、普通に手に入ることがあります。公開して大丈夫なのか、という疑問が出ます。似た道具は裏にも出回ります。隠すと、守りたい側だけが試せなくなります。許可を取ったうえで同じ入り方を試し、穴を先に見つける作業をペネトレーションテストと呼びます。ホワイトハッカーは、その作業で穴を報告したり、企業で対策を進めたりします。表で試せるようにした方が、穴は塞がりやすい、という考えです。道具が出ているのは、無許可の侵入を勧めるためではなく、守る側が同じ地図を持つためでもあります。

黒い画面で起きていることは、だいたい、ログイン文の組み立てをずらすか、偏りのある候補パスワードを流し込むか、公開された道具で同じ試し方を回すか、その組み合わせです。プログラミングの言葉は分からなくても、ロジックが分かれば、ハッキングの仕組みは見えます。
