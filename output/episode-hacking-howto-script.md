# 台本：ハッキングってどうやるの！？

みなさんは、映画やドラマで、ハッカーが黒い画面に緑の文字を打ち込んでハッキングするシーンを見たことはありませんか。そこでハッカーは、何を、どうやっているのでしょうか。

ハッキングとは、コンピュータやネットワーク、プログラムの仕組みを調べ、想定外の動きや穴を見つける行為を指すことが多いです。この言葉自体は、最初から悪事だけを指すわけではありません。許可を取ったうえで穴を探し、直すために報告する人たちもおり、企業に雇われてセキュリティ対策などを行う人たちもいて、ホワイトハッカーと呼ばれることがあります。

インターネット上の悪事としては、ハッキングとは別に、フィッシングもあります。本物の案内やログイン画面に見せかけた偽サイトを用意し、相手からパスワードや確認コードなどを出させる詐欺です。不特定多数にばらまいてだますのが特徴です。

ここでの話では、特定のターゲットを狙うハッキングを、三つの軸に分けて紹介します。

一つ目は、パスワードを探し当てる方法です。攻撃する側は、よく使われる定番パスワードを次々試すことがあります。これを辞書攻撃と呼びます。

辞書の中身は、でたらめな並びではありません。過去の大規模流出で実際に使われていたパスワードを集め、使われた回数が多いものから順に並べたリストがあります。人のパスワードの付け方は均等ではなく、一部の定番に大きく偏ります。覚えやすさや入力のしやすさを優先すると、同じ候補に人が集まります。キーボードの左上から順に押しただけの並び、数字を一から六まで並べただけの列、パスワードという英単語そのもの、アイラブユーのような短い定番、adminのような管理用にありがちな語が、何度も顔を出します。年号を足しただけの短い語や、名前に数字を足しただけの形も、同じように上位へ上がりやすいです。そのため、出現頻度の高い候補から潰すと、総当たりより少ない回数で当たる見込みが上がります。リストの先頭のごく一部だけで、流出データのかなりの割合を占めることもあり、使われた回数が多い順、つまりリストの先頭から試す意味はそこにあります。

別のやり方として、どこかで流出したメールとパスワードの組を、別のサービスでも次々試すものがあります。辞書攻撃がよくある文字列を当てるのに対し、こちらは、別サイトで本当に使われた組を横流しします。人がパスワードを使い回すほど、この横流しが通りやすくなります。

いずれにせよ、それらを手で一文字ずつ打ち直しているわけではありません。ログイン画面は、見た目は人間向けですが、裏側では入力内容をサーバーへ送り、合っているかどうかを返事としてもらう、というやり取りです。攻撃する側のプログラムは、候補のリストをまとめて読み込み、ログインを受け付ける宛先へ向けて、候補を次々と流し込みます。一つ送っては返事を見て、失敗ならすぐ次、また失敗ならまた次、という処理を止めずに回し、成功を示す返事が出た瞬間に正解として抜き出します。画面を開く必要もなく、人がボタンを押す必要もなく、リストをサーバーへ流し込んで一気に当たりを探す、という動きです。人間が画面を見ながら打つ間隔とは、比べものになりません。

さらには、いま多くのサービスには入力回数の制限があります。同じアカウント、または同じ接続元から、短時間に失敗が続くと、一時的に受け付けを止める、追加の確認を求める、といった仕組みです。リストをそのまま一気に流し込むだけでは、すぐ止まりやすいです。攻撃する側は、回数のカウントが紐づいている接続元を切り替えたり、ログイン画面とは別の入口へ移ったり、回数制限の弱い古い管理画面を狙ったりして、制限をかわしたり、カウントを振り直したりします。制限の効き方が入口ごとに違うことが、ここに効いてきます。

二つ目は、特定の相手のスマホやパソコンです。狙うのは、ログイン画面への入力ではなく、端末の操作権限そのものです。狙った相手に請求書だという添付を開かせたり、公式っぽい偽アプリを入れさせたりすると、その人の権限でプログラムが動き始めます。遠隔から魔法で操作しているのではなく、相手の端末の上で、相手と同じ権限の処理が走ります。その結果、ブラウザに保存したパスワードや、ログイン状態の情報を読み出し、本人のつもりで別サービスへ入れます。不特定多数に暗号化するプログラムをばらまく話は、今回の特定ターゲットのハッキングからは外します。

三つ目は、特定のサービスのシステムの穴です。多くのウェブサービスは、ログイン時にデータベースへ問い合わせます。データベースとは、登録情報を表の形で保管しておく仕組みです。その問い合わせはSQLと呼ばれる文で書かれ、登録済みユーザーの表から、入力されたメールとパスワードが一致する行を探し、見つかればログインできます。

本来、入力欄に入るものはデータとして扱われるべきです。ところが、入力をそのままSQLの文へつなぎ合わせると、利用者の文字が命令の一部として読まれ、データと命令の境目が崩れます。この系統をインジェクション、つまり注入と呼び、代表例がSQLインジェクションです。データの文字列として閉じるべきところを途中で終わらせ、いつも成立する条件を足し、後ろのパスワード照合などを無視させます。すると、一致確認が効かなくなり、表の先頭に近い人などで通ってしまう場合があります。画面にはSQL文は見えませんが、奥ではこういう文が組まれているはずだ、と推測して試します。

システムの穴はSQLだけではありません。更新されていないソフト、初期パスワードのままの管理画面、外に開いた入口なども突かれます。脆弱性とは、システムに残った隙や欠陥のことです。

外に開いた入口の一例が、VPNです。VPNとは、離れた場所から社内ネットワークへ、暗号化された道で入る仕組みです。通信の途中を読まれにくくするための道、という側面が強調され、安全な遠隔接続として勧められることが多いです。一方で、会社のVPN装置は、インターネットに面した正規の入口でもあります。一度その入口を通ると、社内の他の機器へ届きやすくなります。更新が遅れたVPNの穴や、VPN用アカウントの弱いパスワード、流出した組の使い回しが、社内へ入る最初の一歩になる事例が続いています。道が暗号化されていても、入口の鍵や入口装置の穴が弱いと、守りはそこで終わります。

映画では、夜のオフィスビルで、ロビーの防犯カメラ映像だけを、人が通っていない録画に差し替える場面があります。

ターゲットは、そのビルの監視システムです。各カメラは映像の流れを録画装置へ送り、監視モニターは録画装置側が出す映像を表示します。差し替える対象はレンズそのものではなく、録画装置が出す映像の選択です。この場面では、ビル管理会社が遠隔保守のためにVPNで社内へ入れるようにしており、そのVPN装置の更新が遅れています。

まず、インターネットに出ているそのVPNの穴から、ビル管理側のネットワークへ入ります。パスワードを当てるのではなく、更新されていないVPN装置というシステムの穴を突きます。VPNを通ったあとは、社内の機器へ届く位置に立てます。

次に、入ったネットワークの中から、映像を集めている録画装置の管理画面を見つけます。社内ネットワークの中でたどり着ける場所に、管理用の画面が開きます。

その管理画面には、定番に近いパスワードが残っており、辞書攻撃と同じ要領で入れます。

最後に、ライブ映像の代わりに、事前に用意した空のロビー映像を繰り返し流す設定に切り替えます。モニターは録画装置の出力を見ているだけなので、出力側をループに変えると、監視側には平常が続き、実際のロビーでは別のことが起きていても届きません。

映画の黒い画面は、こうした管理操作を短く見せている、と考えてよいです。

ホワイトハッカーは、許可を取ったうえで、同じ入り方をわざと試し、穴を先に見つけます。この作業をペネトレーションテストと呼びます。守りたい側が、攻撃する側と同じ地図を持つための作業です。そのために、練習用の環境や穴を確認する道具が表で手に入ることもあります。似た道具は裏にも出回るため、隠すと守る側だけが試せなくなります。公開して試せるようにした方が、穴は塞がりやすい、という考えです。

ばらまき型の暗号化被害もニュースになります。サントリーの広報委託先が暗号化被害を受け、関連する個人情報が影響した可能性がある、といった事例もありますが、ああしたばらまきは今回の三つの軸からは外しています。

辞書攻撃は、ログインという合否のやり取りをプログラムで回し、出現頻度の高い候補から潰す手法です。端末を狙う話は、相手の権限でプログラムを走らせ、保存された秘密に触れる手法です。SQLインジェクションは、データと命令の境目が崩れる手法です。VPNは暗号化された道であると同時に、社内への正規入口でもあります。映画のカメラ差し替えは、その入口から録画装置の出力選択までを握る、一本の操作の話です。黒い画面で起きていることは、だいたいこの三つの軸のどれか、またはその組み合わせです。
